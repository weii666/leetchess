# poc/ — 本地可玩 POC(人执红、引擎执黑)

一次性开发验证,**不是** DESIGN 的最终形态。最终 `web/` 为纯前端 WASM、无后端;
此 POC 用一个本地小后端包住 native `engine/pikafish`,以最快速度验证「人机对弈 + 终局判定」跑得通。

## 前置

引擎档案须先就位(binary + nnue):

```sh
engine/fetch.sh
```

## 启动

```sh
python3 poc/server.py          # 预设 http://127.0.0.1:8000
PORT=8123 python3 poc/server.py  # 指定埠
```

浏览器开 `http://127.0.0.1:8000`。

## 玩法与边界

- 载入《适情雅趣》第21局「尽善克终」(红先必胜,最长杀着 16)。
- 点红子 → 蓝点为合法落点(合法着由引擎 `go perft 1` 给,前端不判规则)。
- 走子后引擎自动应黑方(`go nodes`)。
- **只在真终局停局**:轮到的一方无合法着 → 该方负 → 显示「红胜」/「黑胜」。不提早、不强迫重来。
- 侧栏有**三态诊询信号**(读引擎 `mate` 分数,黑方视角,DESIGN §6):
  - `mate -N` → **即将红胜**(杀着倒数 N)
  - `mate +N` → **即将黑胜**(黑方 N 步内杀)
  - `cp`(未搜到杀) → **未知中立**(诚实地说未知;`cp` 不可据以判走脱)
- 信号仅供参考、会抖、未知偏多(见 DESIGN §6),**不决定停局**——停局只认真终局。

**判定表(离线预解表)不在 POC 内**,亦非本模式的必要件:走脱与否交给信号 + 真终局呈现。
待需要「就是这一步」的移动级确定回馈时再上判定表(DESIGN §6 原案),届时与信号并存。

## 与 DESIGN 的对应

- 引擎 stateless、每次重送完整 `position fen … moves …`:DESIGN §1/§3。
- 胜负只认引擎(合法着数 = 0):DESIGN §7。
- 后端 `Engine` 类即 `EngineAdapter` 的本地实作雏形:DESIGN §9。日后换 WASM 只动引擎存取层。
